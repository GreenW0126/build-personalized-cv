# 中间产物模型

按需使用，不要求用户手动填写所有字段，也不将这些标题原样塞进最终 CV。

## 求职语境卡

```markdown
### 求职语境
- 当前地区：
- 目标地区与市场：
- 可接受条件：
- 不可接受条件：
- 已知方向：
- 尚未确定：
- 工作方式偏好：
```

## 私有经历记录

```markdown
### 经历：<私有工作标签>
- 情境与限制：
- 实际行动：
- 做出的判断：
- 观察或体会：
- 产出或可观察影响：
- 可靠数字及口径：
- 这段经历不能证明什么：
- 信息状态：事实 / 用户解释 / AI 假设 / 待确认
```

## 经历处理队列

```markdown
### 经历处理队列
- 当前：<经历标签>
- 已收口：<经历标签与简短状态>
- 待处理：<按顺序列出>
- 暂时跳过：<低相关或用户选择跳过>
```

## 经历收口卡

```markdown
### 这一段先收口：<经历标签>
- 已确认的核心事实：
- 可能支持的能力：
- 仍缺但不阻塞：
- 状态：够用 / 低相关跳过 / 待定回访
- 下一段：<经历标签>
```

收口卡要短，不复述整段访谈。它的作用是确认当前信息已够用、保存可回访缺口，并把协作显式移到下一段。

## 能力积木

```markdown
### 能力积木：<可重复结果或复合能力>
- 核心能力：
- 支持经历：
- 可观察证据：
- 方法与工作环境：
- 可迁移业务价值：
- 目标岗位使用的语言：
- 无证据的相邻能力：
- 用户状态：确认 / 修改 / 拒绝 / 待确认
```

能力积木应比单条 bullet 更稳定，比“沟通能力强”等性格标签更具体。

## 职业主线假设

```markdown
### 主线假设：<简洁表述>
- 重复选择或行为：
- 支持经历：
- 反例或缺失证据：
- 职业意义：
- 维护成本检查：
- 用户状态：准确 / 部分准确 / 勉强 / 拒绝
```

## 岗位搜索词表

```markdown
### 可能岗位类型：<工作名称>
- 直接岗位名称：
- 相邻岗位名称：
- 业务问题词：
- 能力关键词：
- 行业或本地市场词：
- 需要从真实 JD 验证的词：
```

## JD 证据映射

```markdown
| JD 要求或原句 | 底层能力 | 已有证据 | 匹配程度 | 使用 / 差距 / 待验证 |
|---|---|---|---|---|
```

## 岗位类型 CV 架构

```markdown
### CV 版本：<岗位类型>

- 首要能力积木：
- 次要能力积木：
- 前置证据：
- 模块顺序与篇幅：
- 目标市场语言：
- 刻意弱化：
- 用户状态：确认 / 修改 / 待确认
```
