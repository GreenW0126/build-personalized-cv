# build-personalized-cv

一个用于在 Codex 中共创个性化 CV 的 Skill。

它不把旧 CV 直接润色成一份“看起来更专业”的文本，而是先理解求职语境与真实经历，再把证据整理为可复用的能力积木、可信的职业主线，以及面向不同岗位类型的一页 CV。

> 当前版本：`0.3.0` · 默认支持自动触发，也可以使用 `$build-personalized-cv` 手动调用。

## 它解决什么问题

许多人的经历并不沿着单一职位名称线性发展。常见困难不是“没有经历”，而是：

- 不知道哪些经历真正能证明能力；
- 经历很多、很跳跃，难以形成可信主线；
- 为不同岗位改 CV 时只会替换关键词；
- AI 容易补写动机、夸大影响或生成低信息密度的套话；
- 访谈容易困在某一段经历里不停追问，迟迟看不到全貌。

这个 Skill 把 CV 共创视为一个有状态的证据整理过程。它要求 AI 先建立经历清单，再逐段有限深挖；信息够用时主动收口并进入下一段。

## 核心方法

### 1. 真实证据先于漂亮故事

能力、数字、影响程度与职业主线都必须能追溯到用户实际做过、选择过、观察到或产出的事情。证据不足时保留未知，不补全一个“合理”的故事。

### 2. 把经历抽象成能力积木

能力积木不是“沟通能力强”一类性格标签，也不是照抄 JD 关键词。它描述的是：一个人能在什么条件下，反复完成什么，并为业务带来什么可迁移价值。

稳定的是能力积木；变化的是不同岗位类型中的摆放顺序、证据、语言和篇幅。

### 3. 从行为轨迹发现职业主线

主线来自跨经历重复出现的选择、问题偏好和工作方式，而不是倒推一个完美职业规划。好的主线不需要用户持续维护额外人设，也经得住具体追问。

### 4. 先覆盖，再深挖，逐段收口

收到多段经历后，Skill 会先建立处理队列。每段默认最多两轮集中追问，每轮最多三个相关问题。只有答案可能改变能力判断、岗位方向、职业主线或 CV 表达时，才继续追问。

当信息已经够用、边际价值降低或用户想换一段时，AI 应输出简短的经历收口卡，并明确进入下一段。

### 5. 人保留市场判断与最终声音

AI 可以生成岗位搜索词、拆解代表性 JD 并协助压缩文本，但第一次市场浏览与最终实质编辑由用户完成。最终校对阶段只检查语言与一致性，不重新扩写或强化成就。

## 工作流程

| 阶段 | 目标 | 主要产物 |
|---|---|---|
| 1. 求职语境 | 理解地区、约束、方向和工作方式偏好 | 求职语境卡 |
| 2. 经历证据 | 区分事实、解释、假设与未知 | 经历记录、处理队列、收口卡 |
| 3. 能力积木 | 抽象可重复、可迁移的复合能力 | 能力积木表 |
| 4. 职业主线 | 从重复行为中提出可信主线 | 主线假设与反例 |
| 5. 人工市场校准 | 让用户先形成真实岗位感觉 | 搜索词表、JD 证据映射 |
| 6. 岗位类型架构 | 为真正不同的方向安排重点 | 岗位类型 CV 架构 |
| 7. 分段写作 | 将已确认资产编译成紧凑文本 | 一页 CV 草稿 |
| 8. 人类终稿与校对 | 交还取舍和最终声音 | 受限校对版 |

详细阶段条件见 [`references/stages.md`](references/stages.md)。

## 安装

### 方式一：让 Codex 安装

在 Codex 中调用 `$skill-installer`，并发送：

```text
请从 https://github.com/GreenW0126/build-personalized-cv 安装这个 Skill。
```

安装完成后，在下一轮对话或新任务中使用。

### 方式二：终端安装

将仓库克隆到个人 Skills 目录：

```bash
git clone https://github.com/GreenW0126/build-personalized-cv.git ~/.codex/skills/build-personalized-cv
```

更新已安装版本：

```bash
git -C ~/.codex/skills/build-personalized-cv pull --ff-only
```

如果设置了自定义 `CODEX_HOME`，请将目标目录改为 `$CODEX_HOME/skills/build-personalized-cv`。

## 开始使用

显式调用：

```text
$build-personalized-cv 我想从现有 CV 开始，先帮我建立经历清单，不要直接重写全文。
```

也可以自然描述需求，让 Codex 自动判断是否调用：

```text
我的经历比较跳跃。我希望先把经历整理成能力积木，再为两个不同岗位方向设计 CV。
```

建议准备以下材料，但不需要一次全部填完：

- 现有 CV 或经历列表；
- 当前地区与目标市场；
- 可以接受和不能接受的工作条件；
- 对每段经历的自然叙述，包括行动、判断、观察、产出和可靠数字；
- 尚未确定的岗位方向也可以直接说明。

## 你可以控制访谈节奏

在任何时候都可以直接说：

- “这一段差不多了，进入下一段。”
- “这段先跳过。”
- “继续深挖这一段。”
- “返回上一段。”
- “先给我看当前经历队列。”

即使用户不主动提醒，Skill 也应在达到追问预算或信息边际价值降低时主动收口。

## 明确边界

这个 Skill 不负责：

- 自动抓取或批量爬取职位；
- 替用户完成第一次市场判断；
- 自动投递；
- 逐条 JD 机械重写 CV；
- 求职招呼语或面试准备；
- 承诺通过 ATS、获得面试或 offer。

它的直接目标是帮助用户形成真实、紧凑、可调整的 CV 证据架构。

## 隐私提示

CV 和经历叙述通常包含个人信息。公开反馈问题时，请删除或改写姓名、联系方式、公司内部数据、未公开项目、精确财务数字及其他可识别信息。仓库中的行为案例只描述方法，不应包含真实用户的私有经历。
